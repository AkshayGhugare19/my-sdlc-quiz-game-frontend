CAR models for the Racing game (carBuilder.js, shared by ThreeRaceScene and the
pre-race ThreeCarPreviewScene):

  ACTIVE: car.glb / car-apex.glb (identical) / car-titan.glb / car-ranger.glb /
  car-classic.glb — user-supplied GLB assets. Verify their original source
  license before shipping. No car-nimbus.glb was supplied, so 'nimbus' falls
  back to the shared car.glb per the lookup order below.

  COMPRESSED with gltf-transform (texture resize to 1024 + prune/dedup only).
  The originals were 71MB/27MB/30MB/30MB and were freezing the page for
  several seconds on load (a synchronous bounding-box pass over a 71MB mesh
  blocks the main thread):
    car.glb / car-apex.glb (identical)   71.2MB → 25.1MB
    car-titan.glb                        27.4MB → 13.9MB
    car-ranger.glb                        29.6MB → 8.7MB
    car-classic.glb                      30.4MB → 13.2MB
  Recipe used:
    npx @gltf-transform/cli optimize IN OUT --texture-compress false --compress false --simplify false
  ⚠ DO NOT use `--compress meshopt` (the `optimize` command's DEFAULT) or
  `--simplify true` (which also triggers meshopt to store the simplified
  mesh) for these — that applies EXT_meshopt_compression, which makes the
  file *require* a Meshopt decoder to load at all. Our GLTFLoader in
  carBuilder.js doesn't register one, so a meshopt-compressed file fails to
  load *silently* — no console error — and just falls back to the
  procedural car, which is exactly the bug that shipped here once already.
  `--compress quantize` (KHR_mesh_quantization) is fine — same as the tree
  models below — three.js's GLTFLoader supports it natively out of the box.
  webp texture compression wasn't available either — the `sharp`/libvips
  texture codec errored on this machine ("colourspace: parameter space not
  set") — so textures stay PNG/JPEG at 1024px. If a future machine has a
  working sharp/libvips install, add `--texture-compress webp` to shrink
  these further (see the tree-model two-step recipe below as a fallback).

  ⚠ KNOWN LIMITATION — cockpit/inside view (the HUD's 🎥 camera-toggle
  button) looks dark/wrong with a real model loaded. Its camera sits at a
  fixed eye point (car-local, tuned to the procedural body's own interior
  proportions in carBuilder.js's `parts.eyePoint`) — for an arbitrary
  real model that point can end up inside solid dashboard/seat geometry,
  which renders as black. The outside/chase view and the pre-race showcase
  are unaffected. Fixing this properly needs either a per-model eye-point
  marker or hiding the cockpit toggle whenever a real model is active —
  not done yet, flag it if it matters.

  ⚠ Also noticeable in the pre-race showcase: a couple of stray flat shapes
  float near the car (not attached to it) — likely a decal/sticker or
  shadow-catcher plane baked into the source file at an odd position. Harmless
  visually once actually racing (camera's further away), but worth trimming
  from the source file if you want the showcase fully clean.

  Drop a .glb here named EITHER (for any NEW/replacement car model):
    car-<designId>.glb   — used only for that one CAR_DESIGNS entry (see
                            carBuilder.js), e.g. car-apex.glb, car-titan.glb,
                            car-nimbus.glb, car-ranger.glb, car-classic.glb
    car.glb               — used as the shared default for every design that
                            doesn't have its own car-<designId>.glb
  loadRealCarBody() in carBuilder.js tries the per-design file first, then the
  shared default, then gives up silently — no code change needed either way.

  It's a FULL REPLACEMENT, not a combination — as soon as it loads it hides
  the entire procedural car (body shell, wheels + axles, driver figure) so
  nothing procedural shows through it or doubles up alongside it (no extra
  wheels, no driver floating on a roof that isn't there). Your model should
  therefore include its own wheels. The tail light glow, exhaust flame/smoke
  (correct/wrong-answer feedback), and the name plate stay put on top of it
  either way, so that feedback and garage accessories keep working regardless
  of which body is in use. It's auto-scaled to the procedural chassis length
  (~3.7 units) and dropped to sit on the ground — no manual scale/position
  needed. If your model has NO wheels of its own (body-only), tell me and
  I'll switch it back to keeping the procedural wheels visible instead.

  Where to get one (free, real-time-game-ready, easy license):
    - Kenney.nl (kenney.nl/assets) — CC0 low-poly car packs; closest match to
      this game's existing style, search "car kit" / "racing kit".
    - Poly Pizza (poly.pizza) — free CC0/CC-BY glTF models, search "car".
    - Sketchfab (sketchfab.com) — filter Downloadable + a CC license, search
      "car" or "sports car"; export/download as glTF/GLB if not already.
  Export as glTF Binary (.glb) with textures embedded (single file, no loose
  .bin/.png beside it) — that's what GLTFLoader expects here.

      exported from Adobe Mixamo (https://www.mixamo.com), FBX Binary, With Skin,

ALTERNATE runner (kept as a CC0 option; not loaded unless RUNNER_MODEL_URL points to it):
  runner.glb

The loader picks GLTFLoader vs FBXLoader automatically by file extension. If the
model fails to load for any reason, the fully-procedural cel-shaded runner
(buildCharacter in ThreeSubwayScene.js) is used as an automatic fallback.

SCENERY trees (loaded by loadTrees() in ThreeSubwayScene.js):
  All slots are STATIC GLB trees drawn from one weighted pool (via swapTrees()).
  None is pre-animated — a cheap procedural wind-sway (rotation.z on each tree's
  base, own phase/speed) is applied in update() so the roadside still feels alive.
    real_tree_model1.glb — maple; lightest geom (~16k verts), weighted 3× (most common).
    real_tree_model2.glb — euro beech; moderate geom (~29k verts), weighted 2×.
    coconut_palm.glb     — palm; light, weighted 2×.
    mango_tree.glb       — mango; heavy geom (~100k verts), weighted 1× (rare accent).
  All are user-supplied GLB assets (Sketchfab-authored) — verify their original
  source licenses before shipping. If any fails to load, those slots stay
  procedural cones. (Removed earlier: stylized_tree.glb, tree_animate.glb.)

  COMPRESSED with gltf-transform (all decoder-free at runtime: EXT_texture_webp +
  KHR_mesh_quantization, both natively supported by three.js GLTFLoader):
    coconut_palm       12MB  → 1.7MB  (resize 1024 + webp)
    mango_tree         11MB  → 3.2MB  (simplify --ratio 0.28 + webp + quantize; leaf cards resist simplify)
    real_tree_model1  3.3MB  → 0.9MB  (webp + quantize)
    real_tree_model2  5.7MB  → 2.1MB  (webp + quantize)
  Recipes (textures-only):
    npx @gltf-transform/cli resize IN tmp.glb --width 1024 --height 1024
    npx @gltf-transform/cli webp tmp.glb OUT --quality 85
  For high-poly geometry add:  simplify --ratio 0.05 --error 0.05  then  quantize
  If a model uses KHR_materials_pbrSpecularGlossiness (dropped by modern three),
  convert first:  npx @gltf-transform/cli metalrough IN OUT
